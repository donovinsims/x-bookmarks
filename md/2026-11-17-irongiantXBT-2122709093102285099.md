# holy f*ck this is smart

## Post

holy f*ck this is smart

a 16-year-old cs student in china worked out how to run 300 grok bots for under $0.02 per bot per week

the same swarm would burn $4,500 a week without it

he cut pointless status checks, stopped rereading full chat histories and killed every endless retry loop

now most bots stay idle until there's real work to do

here are the 20 github repos he used to bring the cost down:

1. markitdown > convert pdfs, office files and html into clean markdown before analysis so the bot reads the content, not the layout
https://github.com/microsoft/markitdown

2. llmlingua > compress long inputs before the model reads them while keeping the facts, constraints and qualifications the task depends on
https://github.com/microsoft/llmlingua

3. firecrawl > collect web content as markdown or structured data so the workflow keeps only the fields it needs
https://github.com/firecrawl/firecrawl

4. rtk > compress common command outputs before they enter the conversation so repetitive logs don't swallow useful context
https://github.com/rtk-ai/rtk

5. chonkie > split long documents into chunks so retrieval pulls the relevant passages instead of the whole file
https://github.com/feyninc/chonkie

6. flagembedding > rerank retrieved passages before generation - strong evidence stays, irrelevant matches leave the prompt
https://github.com/flagopen/flagembedding

7. mem0 > store and retrieve relevant facts across runs so each task starts with selected memory instead of the entire conversation
https://github.com/mem0ai/mem0

8. prefect > cache successful task results and reuse them when configured inputs match, skipping reruns of steps that already finished
https://github.com/prefecthq/prefect

9. gptcache > serve saved answers to similar requests instead of generating again - set matching and freshness rules around the task
https://github.com/zilliztech/gptcache

10. graphiti > keep changing facts in a searchable graph and pull relevant context instead of replaying the full event history
https://github.com/getzep/graphiti

11. portkey gateway > cache matching api responses behind one shared gateway so connected workflows reuse answers across repeated requests
https://github.com/portkey-ai/gateway

12. hishel > add http caching and revalidation to your fetching tools so unchanged responses stay out of repeated download-and-analysis cycles
https://github.com/karpetrosyan/hishel

13. celery > put background jobs on a worker queue - code handles waiting and dispatch, model calls run only inside tasks that need them
https://github.com/celery/celery

14. requests-cache > store fetched responses with expiry rules so your scripts reuse valid data before asking the bot to look again
https://github.com/requests-cache/requests-cache

15. apscheduler > run lightweight checks on a schedule in python and batch nonurgent work before passing useful updates to the agent
https://github.com/agronholm/apscheduler

16. routellm > send simpler requests to a cheaper model and keep the stronger one for work that needs it
https://github.com/lm-sys/routellm

17. phoenix > trace your ai workflow, inspect repeated calls and compare changes against output quality before keeping an "optimization"
https://github.com/arize-ai/phoenix

18. pybreaker > pause calls to a service that keeps failing once it hits a set threshold, so one broken dependency can't loop forever
https://github.com/danielfm/pybreaker

19. semantic router > match requests to predefined workflows with local embeddings instead of paying a large model to pick every next step
https://github.com/aurelio-labs/semantic-router

20. litellm > track api spending and set budgets before one runaway workflow eats the whole allowance
https://github.com/berriai/litellm

connect the tools your workflow needs through the terminal, mcp or your own code - route api calls through the gateway you picked so its controls actually apply

start with the biggest leak: oversized inputs, repeated research, empty checks or failed operations that keep restarting

filter before reading > reuse before generating > check for changes > stop failed loops

then measure finished work against total usage, including the tools running around your bot
