# REA + GrokBot: Reverse Engineer Apps and Build Your Own Features (Full Guide)

## Post

You see a feature in an app and immediately think:

“I wish I could build that”

So you send AI a screenshot. It recreates the layout. Then you click something and discover how much it guessed.

The screenshot showed the interface. It never showed the rules.

This is where GrokBot + REA gets interesting. Give the agent something it can inspect, ask one precise question, and make it connect the explanation to evidence.

Then decide what your own version should do.

This guide uses three official REA case studies to explain the method, followed by GrokBot-specific connection instructions and a reusable build workflow. The published examples are credited to their sources; they are not presented as experiments I ran with GrokBot.

First, see the idea

This video post introduces REA and the kinds of questions people bring to it. Treat it as an introduction, then use the primary-source examples below for the technical detail.

Three doors into an application

Different targets need different evidence. A packaged desktop app, an Android APK and a native executable do not become understandable in exactly the same way.

The useful question stays the same: which rule causes the behavior I can see?

01 / The feature hiding behind “Copy”

Copying a block feels like one action. Internally, more than one representation can matter.

REA’s Notion case study follows a clipboard request from the page-facing API through Electron’s process bridge to the clipboard writer. It also describes a local block-data mechanism tied to an identifier carried in HTML.

That gives you a better investigation question than “clone this editor”: what is preserved when content crosses the clipboard boundary?

Your project could be a focused clipboard utility or an export helper. You choose the requirements after understanding the boundary.

02 / The hidden rule behind a changing number

The Aegis case study starts with a visible behavior: a six-digit login code changes with time.

REA locates the generating methods in the Android APK. The official interactive demo lets you move a test clock and see the boundary between time blocks. It uses public test data, not a real account secret.

The authors report 133 comparisons between selected REA-returned methods and an independent reconstruction. That validates the reported cases, not every possible app behavior.

03 / When the first answer is incomplete

Native software can produce a deceptively small decompiler result.

In REA’s DX-Ball example, an initial view omitted useful details about the sound-pan calculation. Following instructions, a caller and stored constants exposed the relationship between horizontal position and the panning value.

The reported reconstruction of that single function was checked against 3,205 input cases and 63 compiled bytes. Those numbers apply to the function, not a claim that the entire game was finished.

Before you call it a replacement

Check a normal input, an empty input, a boundary and a failure. Make sure the comparison would catch an intentionally wrong result.

Also check the boundary of your claim. Client inspection does not reveal a private server’s source. Three passing examples do not establish complete compatibility. A rebuilt feature does not mean a whole app has been recreated.

REA is open source; agent usage, hosting and some providers can still cost money. Analysis results reach your agent and are subject to its model provider’s data policy. Use targets you own or are authorized to examine.
