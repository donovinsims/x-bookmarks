# How To Reverse Engineer Any Device With Claude Code (Full Setup Included)

## Post

Inside: REA as your agent's hub, GhidraMCP for firmware, and mitmproxy for seeing what devices send.

Set it up once and any device gets mapped in an afternoon with free, open-source tools.

Here's the full setup 👇

Before we dive in, I publish full guides like this on my Substack: https://substack.com/@cabbitar 🧠

What "any device" means in this guide

Every device runs software. A smart plug runs firmware, a phone runs APKs, a desktop app is a native binary or an Electron bundle, and almost all of them talk to a server somewhere. Reverse engineering is reading that software when nobody gave you the docs.

Real reasons people do this:

see which servers a smart camera calls home to, and how often

keep a gadget working after the vendor shuts down its cloud

understand a file format an app needs to read

debug a release build of an app that behaves differently from dev

copy a feature you like into your own project, rebuilt from scratch

How the stack fits together

You ask Claude Code a question, Claude Code passes it to REA through MCP, and REA calls the engine that fits the target: Ghidra for native code and firmware, JADX for Android, its own parsers for Electron, .NET and dozens of file formats. Every answer comes back with evidence attached, so Claude can show you the function address or the request that proves a claim.

You only touch the specialist tools (x64dbg, Frida, ImHex) when the agent asks for them or when you want to poke around yourself.

Step 2: Add Ghidra and GhidraMCP (5 minutes)

Ghidra is the NSA's free decompiler. It turns machine code for x86, ARM, MIPS and many other chips back into readable C-like pseudocode, so you can read firmware from a router or smart plug. GhidraMCP (11.8K stars) lets Claude drive it directly.

Install Ghidra 12.1.4 from ghidra-sre.org (it needs a JDK, the release page names the version).

Download the latest GhidraMCP release from github.com/LaurieWired/GhidraMCP.

In Ghidra: File → Install Extensions → + → pick the GhidraMCP.zip from the release.

Restart Ghidra and check the plugin is enabled under File → Configure → Developer.

Install uv, then register the server with Claude Code:

Open a binary in Ghidra, then ask Claude to list its functions. If it answers with real names and addresses, the bridge works.

Ghidra's plugin listens on port 8080 by default. mitmproxy uses the same port, so in Step 4 you'll move mitmproxy to 8082.

Step 3: Build the workspace (Full Files Included)

One folder per device keeps findings from leaking between projects.

.claude/settings.json

Claude can read everything in target/ and has no write access to it, so your original firmware or APK stays clean for comparisons later. The deny list also blocks network calls from the shell, which helps when the code you're reading might try to phone home.

CLAUDE.md

Decompiled code is full of missing names and types, and without the evidence rules Claude fills those holes with guesses. The CONFIRMED / LIKELY / UNKNOWN tags show you which parts to double-check.

On Linux, REA uses Binwalk or Unblob for extraction, then passes native code to Ghidra. When a header doesn't match any known format, open it in ImHex: its pattern language lets you describe the layout once and every byte gets labeled and colored.

What your device sends (network)

mitmproxy sits between your device and the internet and shows every request. Since Ghidra already owns port 8080, start it on another port:

Point your phone or gadget's Wi-Fi proxy at your laptop's IP on port 8082, then open mitm.it on that device to install the certificate. Some devices pin their certificates, and then you'll only see which hostnames they connect to. Often that list is enough to see which companies the device reports to.

REA reads HAR captures directly and returns requests, responses and the source locations behind them.

Android apps

jadx turns the APK back into readable Java. Pair it with jadx-ai-mcp (3.0K stars) so Claude can browse the code.

Apktool decodes the manifest and resources, which lists every permission the app requests.

Frida hooks into a running app on your own build or emulator and logs function arguments live, with no recompile.

REA covers the static side too: with headless JADX and a full JDK installed it returns manifest declarations, classes and decompiled methods, and it can talk to an emulator or your own phone through adb.

Desktop apps

Electron apps (Notion, Slack, Discord and VS Code are all built on it): REA reads these with no extra engine.

.NET apps and Unity games: ILSpy decompiles DLLs back into C#, dnSpy (use the dnSpyEx fork, the original is archived) lets you debug them without source.

Native apps: Ghidra through GhidraMCP for pseudocode. On Windows, x64dbg for stepping through live code, and Epic's RAD Debugger when the program is huge and x64dbg feels slow.

Terminal people: radare2 or its fork rizin, which REA also supports for offline inspection.

"Which input reaches this line?": angr explores every path through a function with symbolic execution and answers that question directly.

Step 5: Rebuild and verify with Craft Anything

Once you know how a feature works, you can build your own version. Craft Anything (16.8K stars, early alpha) runs the whole loop: it studies the original, has Claude Code build a new project, compares the two and refines until they match. It ships 320 tools, each one a CLI command and an MCP tool.

It needs Rust 1.97 or newer. Two modes:

Clean room (the default) works only from what a visitor can see: screenshots, layout, colors, fonts, spacing. Websites get checked at three screen widths.

Deep reads the code and files too, for your private use.

To copy the look and layout of a site or app UI, clean room mode is enough.

In REA's DX-Ball case study, the agent rebuilt the game's sound-pan function in C, and the reconstruction passes 3,205 test cases against the original x86 code.

Common mistakes

Running mitmproxy on port 8080. Ghidra's plugin already sits there, and the clash looks like a broken MCP server. Use -p 8082.

Starting with the hardest tool. If you open x64dbg first, you spend hours in raw assembly before learning anything useful. Start with REA and let the agent call the low-level tools when a task needs them.

Trusting pseudocode blindly. Decompiler output is a best guess. Check anything tagged LIKELY or UNKNOWN by hand, and let Craft Anything's check step compare your rebuild with the original.

Running unknown binaries on your main machine. Use a VM for anything you didn't build yourself.

Working on your only copy of the firmware. Keep originals in target/ (read only) and experiment in scratch/.

Skipping the ground rules. Keep every tool here pointed at devices and software you own or are allowed to examine. Both REA and Craft Anything are built for that.
