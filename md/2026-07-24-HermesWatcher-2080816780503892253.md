# Meet Havoc: Why I Gave Hermes Its Own Manager

## Post

You don't need to memorize every Hermes command. Give one agent the job of managing Hermes itself.
The easiest way I've found to manage Hermes is to stop managing Hermes myself.
I gave one Hermes agent a second job: manage Hermes itself.
I call him Havoc. Ironically, his job is to keep me from causing it.
The idea is simple
Hermes gives you a lot of control: models, fallbacks, profiles, gateways, scheduled jobs, MCP servers, tools, settings, diagnostics, updates, and more.
That flexibility is great. It also creates a growing list of things you may eventually need to configure, maintain, or troubleshoot.
I don't want every routine change to become a documentation project. So instead of starting with, “What command do I need?”, I usually start with, “Havoc, here's what I want changed.”
Havoc inspects the setup, handles the Hermes side of the job, verifies the result, and pulls me in when something genuinely requires me.
There is another reason I prefer having one agent handle this.
I want my other agents specialized in the jobs I created them for. I don't need a content agent, research agent, or coding agent becoming my resident Hermes administrator every time I need a setting changed.
Havoc learns the Hermes side. The other agents stay focused on their side.
That gives me one place to manage the platform without constantly pulling specialized agents away from their actual jobs.
What I actually hand off
I regularly use Havoc for things like:
updating Hermes
changing models for different agents
configuring fallback models
creating and configuring profiles
restarting gateways
changing Hermes settings
creating or changing scheduled jobs
helping configure MCP servers and integrations
running diagnostics when something is not behaving correctly
The list is useful, but the bigger value is what those jobs look like in practice.
Updates that mostly happen without me
Hermes gets updated regularly. In my setup, Havoc has a standing nightly job for Hermes maintenance, so most updates happen without me thinking about them.
When I want an update outside the normal schedule, I don't go looking for the update process. I ask Havoc to handle it and verify the installation afterward.
Hermes already provides the underlying update, configuration-check, backup, and restart workflows. Havoc gives me a simpler way to operate them.
Changing models without managing the mechanics
This is one of the jobs I use most.
I run multiple Hermes agents and change intelligence models depending on the job, provider, cost, or availability. I can tell Havoc which agent I want changed, what model I want, and whether I want a fallback.
Hermes supports per-profile model configuration and fallback providers. If a brand-new provider needs an API key, OAuth login, or another human authorization step, Havoc can get me to that point, but he cannot magically bypass it.
Creating a new profile without feeling like I'm starting over
This one changed how I think about adding agents.
A new profile used to sound like another setup project: new personality, instructions, model, settings, working directory, tools, scheduled jobs, and whatever else that agent needs.
Now I can start with a rough description of the agent I want and let Havoc handle the Hermes setup around it.
That can mean creating or cloning the profile, turning my rough personality notes into a useful SOUL.md, preparing project instructions such as AGENTS.md when appropriate, configuring the model and settings, and then showing me what was created.
Hermes profiles are separate agent environments with their own configuration, credentials, SOUL, memory, skills, cron jobs, sessions, and gateway state. I describe the agent I want. Havoc handles much more of the setup work.
Settings without memorizing config keys
The same idea applies to everyday settings.
I don't necessarily want to remember where a setting lives or what its exact key is. I want to describe the behavior I want changed.
A good manager workflow is simple: inspect the current configuration, identify the right setting, make the requested change, and verify the result. If the change is ambiguous or high impact, stop and ask.
When something breaks
When something breaks, I let Havoc deal with the havoc.
I do not always know whether the problem is a gateway, configuration value, dependency, model provider, or something else before I ask for help. Hermes provides status commands, diagnostics, logs, configuration checks, and a doctor workflow designed to identify setup problems.
So my starting instruction can be outcome-based:
Havoc, figure out why this isn't working. Tell me what you find, fix what you can safely fix, and tell me if you need me for anything.
That is much closer to how I want to use an agent.
Manager, not magic wand
Havoc is not an official Hermes feature or special agent type. It is simply a role I give an agent in my own setup.
What your own Hermes manager can actually change depends on the tools, terminal access, file permissions, credentials, and approval rules you give it.
Some jobs legitimately need you. New API keys, OAuth flows, external account authorization, operating-system permissions, and security approvals can require a human. I also would not give an agent broader permissions than I am comfortable with just to make the idea work.
The goal is not to let an agent blindly control everything. The goal is to give one trusted agent enough context and appropriate access to become the operator for your Hermes installation.
How I would set one up
Choose the agent. Dedicated profile or an agent you already trust.
Define the responsibility. Managing Hermes is part of its job.
Give it appropriate access. Only the tools and permissions needed for the work you want delegated.
Set change rules. Inspect first, protect important state, make the change, verify afterward, and surface anything requiring human approval.
Automate the boring parts. Use scheduled jobs for recurring work that makes sense in your setup.
The bigger point
Hermes is an agent platform. One of the most natural uses of an agent platform is letting an agent help operate the platform itself.
I still decide what I want. Havoc handles more of the “how do I change that?” layer.
Turns out, a little Havoc can make Hermes a lot easier to manage.
And now, whenever I catch myself digging through documentation or trying to remember how to change something in Hermes, I have a much simpler question:
Why am I doing this instead of Havoc?
