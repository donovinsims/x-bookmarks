# Hermes Keeps Forgetting? You Might Be Using the Wrong File.

## Post

You tell Hermes how you like to work. You tweak its personality. You add project rules. Then it acts like it missed the memo.
Before you blame the model, check where the memo went.
Hermes has several Markdown files that shape an agent’s behavior, and they do different jobs. Put the right information in the right place and you can stop treating its entire brain like one giant junk drawer.
Here's the map.
SOUL.md: who your agent is
Want Hermes to be direct, playful, careful, or opinionated? That’s identity and communication style. The durable home for that is `SOUL.md`.
Hermes loads it as the agent’s primary identity at session start. By default it lives at `~/.hermes/SOUL.md`; a custom `HERMES_HOME` changes the location. Hermes creates a starter if one is missing, while existing files are preserved.
A useful instruction might be:
Be direct. Explain tradeoffs in plain language and say when you’re unsure.
That tells the agent how to show up. It doesn't automatically populate your user profile.
USER.md: what Hermes knows about you
Your preferred units, communication preferences, and working expectations belong with the user profile. Hermes maintains `USER.md` through its memory tool, and the default location is `~/.hermes/memories/`.
Try telling the agent something specific:
Remember that I prefer short summaries with the important caveat up front.
Don’t assume it saved the preference just because you asked. Check the memory tool’s response or inspect the appropriate entry using `hermes journey list`. Memory writes can be subject to approval depending on configuration.
MEMORY.md: what the agent has learned
`MEMORY.md` is for the agent’s own durable notes: environment facts, conventions, and useful lessons. Think “this project uses a particular test command,” not “make my agent sound more sarcastic.”
The built-in memory is intentionally bounded. The documentation lists default limits of 2,200 characters for agent memory and 1,375 for the user profile, and those limits are configurable. If the store fills up, the agent needs to make room rather than silently assuming everything fits.
And don’t treat memory as a secret vault. Put sensitive information only where you’re comfortable with the agent and its configured tools accessing it.
AGENTS.md: what this project needs
Project-specific rules belong with the project. An `AGENTS.md` might explain the test command, architecture, coding conventions, or how to handle a particular repository.
Hermes also supports `.hermes.md`, which takes precedence over `AGENTS.md` when both compete as project context types. The documentation describes the precedence as `.hermes.md` → `AGENTS.md` → `CLAUDE.md` → `.cursorrules`. `SOUL.md` is loaded independently.
That distinction matters: a project rule shouldn't need to follow the agent into every unrelated task.
The “it saved it, but still forgot” trap
Here’s the part that trips people up.
 
Screenshot: Hermes documentation explains why a saved memory may not appear in the current session’s injected prompt. Source.
Hermes loads its built-in `MEMORY.md` and `USER.md` into the system prompt as a snapshot at session start. If a memory is saved halfway through a session, it is written to disk, but that injected snapshot doesn’t automatically change in the middle of the session.
The agent can still see what you just said in the current conversation. For the refreshed memory snapshot, start a new session. For long-running gateway conversations, the documentation also describes `hermes sessions refresh-prompts`; check the session documentation before using it.
So if a saved preference appears missing:
Confirm the memory write actually succeeded, including any approval.
Check that you’re using the intended Hermes profile and home.
Start a fresh session and test the preference again.
If the instruction is about the agent’s personality or one project’s rules, check whether it belongs in `SOUL.md` or project context instead.
The cheat sheet
Agent identity and tone: `SOUL.md`
Facts and preferences about you: `USER.md`
Agent’s durable notes and lessons: `MEMORY.md`
Repository or project rules: `AGENTS.md` or `.hermes.md`
Repeatable procedures: a skill
This guide follows the current official documentation; configuration, profiles, and versions can change the details. The examples above are suggested prompts, not a claim that a live memory write was tested.
Start with the file map, then dig into persistent memory and context files when you need the mechanics.
