My app Voicy gets 25,000 clicks a month from Google & ChatGPT.

Not through blog posts, but landing pages. 

Yet almost every “AI SEO” tutorial tells you to do the same thing: write more blog posts.

(my setup is automated with romeoseo.com, but this guide has the free skill files)

Stop making your entire SEO strategy a blog.

A reader searching “what is a CRM” wants an explanation. Someone searching “CRM for small business” is looking for a product. 

Give that person a page that helps them choose yours.

That's where landing pages get powerful. 

ou can answer the search AND sell the product on the same page.

1. Find buyers. Not just big keywords.

Run Site content inventory, then SEO opportunity research.

Give your agent this prompt:

Find searches where someone is choosing a product like ours. Check our existing pages first. Return three opportunities, the competing URLs, available demand evidence and the buyer's next action. Recommend ONE. Tell me whether to improve an existing page or create a new one.

Look for searches about:A platform: “dictation app for Mac.”
A use case: “voice typing for emails.”
An audience: “dictation software for writers.”
An alternative: “[competitor] alternative.”

These are research starting points, not a command to build four pages. Pick the one your product can actually win a customer from.

2. Check what the search needs

Run Search intent match.

Give your agent this prompt:

Inspect the current results for the chosen query. Identify the page types that rank and what the searcher wants to do next. Check our closest existing URL. Recommend the right page format and the specific information ours must include.

Product pages ranking? Build a useful product landing page.

Comparisons ranking? Run Comparison page writer and help the buyer choose.

Guides ranking? Answer the question with a guide. Don't force a sales page into the wrong search.

3. Write the page around ONE decision

Run SEO content brief.

Give your agent this prompt:

Brief a landing page for our approved query. Put the buyer's desired outcome first. Specify the headline, opening screen, product demo, benefits, proof, objections, pricing information and one main call to action. Include the title, proposed URL and internal links. List the real screenshots or facts you need. Keep it a landing page, not a blog post. Wait for my approval.

For a Mac dictation page, the structure could be:

Headline: “Turn speech into text on your Mac.”
Demo: show the real product doing exactly that.
Benefits: show which supported tasks become easier.
Proof: real customer quotes and product screenshots.
Objections: compatibility, accuracy, privacy and price, answered with actual facts.
Action: a clear button matching your offer, such as “Download for Mac.”

Approve the brief. Cut every section that doesn't help someone decide.

4. Make Claude Code or Codex BUILD it

Use the approved brief as the build spec. The SEO skills guide the page; your coding agent handles implementation.

Give your agent this prompt:

Implement the approved landing page in this project. Reuse our components, typography and design system. Make the main benefit, real product image and primary CTA clear on the first screen. Use real copy instead of placeholders. Implement the approved title, description and canonical URL. Keep the important content crawlable. Make it work on mobile. Add conversion tracking using our existing analytics setup. Run the project checks and open a browser preview. Show me the page and changed files before deployment.

Check the page yourself:Can you tell what it sells in five seconds?
Does the screenshot show the promised use case?
Does the button reach the right download, signup or checkout?
Can you use it on your phone without fighting the layout?

A pretty page with a broken signup button is not finished.

5. Make it useful. Make it discoverable.

Run SEO content QA, On-page SEO review and Technical SEO audit against the draft and preview.

Give your agent this prompt:

Check the page against the approved brief and query. Fix vague copy, missing answers, unsupported claims, broken links and mobile problems. Check rendering, indexability settings, canonical URL and image loading. Keep preview environments private. Return the fixes and remaining issues, then rerun failed checks.

Run Internal linking plan.

Give your agent this prompt:

Find relevant pages on our site that should link to this landing page. Recommend the exact source URLs, placements and natural anchor text. Keep links useful to readers. Show the changes for review.

Approve the finished preview. Then tell your agent to deploy and check the live URL again.

6. Count customers. Not just clicks.

Run SEO performance audit once the page has data.

Give your agent this prompt:

Save a baseline at launch. Once we have enough data to compare, review this URL's search impressions, clicks, organic visits, completed signups and tracked sales. Use Search Console for search performance and analytics for conversions. Recommend the next change based on where buyers drop off.

Impressions but few clicks? Rework the title and search promise.

Visits but few CTA clicks? Fix the offer, demo and opening screen.

CTA clicks but few signups? Check the next step before rewriting the whole page.

One useful page working? Research the next distinct buyer need. Don't clone it 100 times and swap the keyword.
