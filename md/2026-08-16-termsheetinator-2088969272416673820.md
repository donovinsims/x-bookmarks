# If you record B2B sales calls in Fathom, build this:

## Post

If you record B2B sales calls in Fathom, build this:

1. Go to Fathom > User Settings > API Access > Generate API Key. (or any notetaker)

2. Go to OpenAI > API Keys > Create API Key.

3. Download & sub to Codex or Grok Bot desktop.

Create a local folder called "companyname-salesops-brain".

4. Save both keys in .env:

FATHOM_API_KEY=[api key]
OPENAI_API_KEY=[api key]

Add .env to .gitignore. Never paste or commit either key.

(Also learn what a .env is for and why it's important, good info to have)

5. Tell Codex:

“Turn this folder into a self-enriching Sales-Ops Brain.

Build a Fathom sync that pulls every new meeting  transcript, tracks meeting IDs in processed.json and never duplicates or overwrites raw calls.

Use the OpenAI API with structured outputs to analyze every transcript and create:

- /calls/raw/ for immutable transcripts
- /calls/enriched/ for one structured .md file per call
- /knowledge/objections.md with exact buyer language
- separate .md files for desired outcomes, buying criteria, winning language, stakeholders, risks, deal stages and next steps
- /reports/daily/ and /reports/monthly/
- /prompts/ for one-shot VSL, deck, email and content prompts
- MEMORY.md for repeated sales patterns
- AGENTS.md for stable operating rules

Every claim must link back to the source call and date.”

I'd create better prompts than the ones in here by explaining what I want the end result to be in a dictation yap session in GPT, and then take that and paste it into the Codex session.

6. Run it once.

Fix the structure until every output is clean, sourced and useful.

7. Open Codex > Scheduled.

This is the easiest version of a cron job.

Create 2 tasks in the local project:

EVERY NIGHT:

“Pull today’s calls. Enrich the new .md files. Update the objection database, sales knowledge and daily report. Promote something into MEMORY.md only when repeated evidence makes it durable. Update AGENTS.md only when an operating rule changes.”

FIRST OF EVERY MONTH:

“Analyze every call from last month. Rank every objection by frequency, deal stage, buyer type and known pipeline value. Include the exact language and source call. Show what appeared, disappeared or increased.

Turn the top objections into one-shot prompts for:

- VSL's
- objection-handling decks
- new deck slides
- objection specific case studies
- sales emails
- objection specific sales content

Make every prompt usable in Claude Code or my preferred deck builder.”

Leave Codex running and the computer on when the tasks are due.

Only process calls you are authorized to send to the model.

THE END RESULT:

Every month, your buyers tell you:

- what they want
- why they hesitate
- what language they use
- what proof is missing
- what your sales assets need to say next

That report becomes the RevOps backlog.

Call > Sales Ops Brain™ > objection > asset > more-sold prospect > better call > repeat.

Every recurring objection must update an asset.
