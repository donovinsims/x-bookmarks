# How to Turn Claude Code Into a $200/Hour Automation Service in 14 Steps

## Post

$20 Claude plan → repeatable client work no agency touches.
A 29-year-old backend developer in Austin spent his evenings writing tests for other people's repos. He charged 40 dollars an hour, billed maybe 12 hours a week, and called it a side income. The work bored him. Claude Code did most of it faster than he could read the diff.

Then he stopped thinking of Claude as a faster keyboard and started thinking of it as the product. Every repeatable job a business pays a human to do by hand is unbilled inventory. Code review, test suites, migrations, doc generation. The work already exists. Somebody is doing it slowly. You package Claude to do it the same way every time, attach a price, and sell the output, not the hours. Here are the 14 steps that turn one terminal into a service.
 
1. Pick one job, not "AI services"
"I do AI automation" sells nothing. "I write your missing test suite in 48 hours, 80% coverage, fixed price" sells. Choose one repeatable task with a clear before and after: code review, test generation, a framework migration, API documentation. One job means one repeatable system. Ten jobs means ten half-built ones.
 
2. Write CLAUDE.md as the client brief
Claude forgets everything between sessions unless you write it down. Drop a CLAUDE.md at the repo root with the client's stack, conventions, branch rules, and the definition of done. This file is the brief Claude reads on every run, so the 50th delivery matches the 1st. Treat it as the contract, not a note.
 
3. Run plan mode before Claude touches code
Press Shift+Tab into plan mode. Claude reads the repo and shows you the plan before it writes a line. You catch the wrong file, the misread requirement, the risky migration while it still costs nothing. On client work, an unsupervised first edit is how you lose a repo and a customer in the same afternoon.
 
4. Build one subagent per task
 
Make .claude/agents/code-reviewer.md. Three lines of frontmatter set its name, its tools, and its model:
 
Add test-writer.md, migrator.md, doc-gen.md. Each agent runs in its own context, so the reviewer never gets confused by the test writer's work. Five specialists beat one overloaded chat.
 
5. Package the job into slash commands
A client engagement is the same five moves every time. Wrap them in /intake and /deliver commands stored in .claude/commands/. One line spins up the whole flow: read the brief, route to the right agent, run the checks, format the output. You stop retyping prompts and start running a procedure.
 
6. Put hooks at the QA gate
 
A PostToolUse hook runs your linter and test suite automatically after Claude edits a file. Nothing reaches the client until it passes. The hook is the difference between "I think it works" and "the tests are green, here is the log." You sell the second one.
 
7. Connect client tools through MCP
Claude Code reads your client's GitHub, a read-only database, their Notion, through MCP servers you add per project. The agent works against real context instead of pasted snippets. Give it read-only access to production and write access only to a working branch.
 
8. Block secrets with deny rules plus a hook
 
In settings.json, deny reads on .env, ~/.ssh/**, and secrets.json. Know the catch: Anthropic calls Read deny a best-effort control, and reported bugs show it can miss files at session start. So back it with a PreToolUse hook that checks the path and hard-blocks the call before it runs. The deny rule is the policy, the hook is the enforcement. A client hands you a repo because they trust that boundary, and keys that never enter context never end up in a transcript.
 
9. Cron the overnight work
 
A review queue does not need you awake. A scheduled job runs the reviewer agent at 2 a.m. against the day's open PRs and leaves comments by morning. The client wakes up to finished work. You wake up to an invoice line.
 
10. Make the output template the deliverable
Same format, every client, every time: a summary, the findings table, the diffs, the test log. Save it as a template the /deliver command fills. A consistent artifact is what a buyer remembers and refers. Surprise formatting reads as amateur.
 
11. Log every command
Pipe each agent action to a dated log file. When a client asks what happened to a file, you show the trail. An audit log is what lets a business trust an AI with their codebase. It also covers you when something breaks and they want to know whose change did it.
 
12. Price the task, not the hour
 
The 200-dollar-an-hour figure is a ceiling you back into, not a rate you announce. Quote the job: 600 dollars for a test suite, 1,200 for a migration. If your system finishes a 1,200-dollar migration in 6 hours, your effective rate is 200. The client buys a fixed outcome and a fixed price. You keep the speed you built.
 
13. Attach the invoice to the delivery
Put a Stripe payment link in the same message as the deliverable, while the value is fresh. No separate invoicing ritual a week later. The client sees the finished test suite and the pay button in one place. Friction removed is money kept.
 
14. Run clients in parallel and productize the stack
The whole setup lives in one repo: agents, commands, hooks, templates, deny rules. Clone it per client, swap the CLAUDE.md, and you onboard in minutes. Subagents run several jobs at once, so 9 clients feel like 2. At that point you are not freelancing. You are running a service with one employee who never sleeps.
