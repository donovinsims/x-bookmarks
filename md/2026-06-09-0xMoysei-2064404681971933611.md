# How to Build an AI Automation Agency With Claude in 14 Steps

## Post

$200/month stack → systems businesses pay $2,000/month to run.
A 27-year-old in Austin spent his weekends building Zapier flows for a friend's dental clinic. Missed-call texts, intake forms, a weekly report nobody had time to pull. The clinic paid him $300 here, $400 there. Small money for work that ran itself once it was set up.

Then he stopped charging for the build and started charging for the outcome. Every repeatable job a business pays a human to do by hand is unbilled inventory. Answering after hours, copying data between tools, chasing leads that went cold. The work already exists. Somebody does it slowly. You wrap Claude to do it the same way every time, attach a retainer, and sell the hours back. Here are the 14 steps that turn one laptop into an agency.
 
1. Sell one outcome, not "AI automation"
"I do AI for businesses" closes nobody. "I recapture every missed call and book it as an appointment, fixed monthly fee" closes. Pick one outcome a business can feel: recovered leads, a cleared inbox, a report that lands every Monday. One outcome means one repeatable system. Five outcomes means five half-built ones and no case study.
 
2. Pick a niche with repeatable pain
Roofers, clinics, law offices, local agencies. Choose a niche where the same problem repeats across every business, because the system you build for one becomes the system you sell to the next. The narrower the niche, the faster your pitch lands and the less you rebuild per client.
 
3. Run the audit before you sell
Call the business 3 times like a customer would. Note what broke: the call went to voicemail at 6 p.m., the form never replied, the quote took 2 days. That audit is your whole pitch. You walk in with the leak already measured, not a generic deck about the future of AI.
 
 
4. Set up Claude Cowork as the agency desk
Cowork reads and writes files on your machine and runs tasks, which is what an agency operation needs. Make one folder per agency with subfolders for each client. This folder is the desk where every brief, asset, and deliverable lives, and Claude works inside it instead of guessing from pasted snippets.
 
5. Write CLAUDE.md as the client brief
Claude forgets everything between sessions unless you write it down. Drop a CLAUDE.md in each client folder with their brand voice, their rules, their definition of done. This file is the brief Claude reads on every run, so the 40th deliverable matches the 1st. Treat it as the contract.
 
6. Build one subagent per task
Make .claude/agents/intake.md, follow-up.md, reporter.md. A few lines of frontmatter set each agent's name, tools, and model:
 
Each agent runs in its own context, so the reporter never gets tangled in the intake work. Specialists beat one overloaded chat.
 
 
7. Connect client tools through MCP
Claude reaches the client's Gmail, Calendar, CRM, and Notion through MCP connectors you add per project. The agent works against real data instead of copy-paste. Give it read access where it only needs to look and write access only where it needs to act.
 
8. Block client data with deny rules and a hook
In settings.json, deny reads on .env, credentials, and anything outside the client folder. Know the catch: Anthropic calls Read deny best-effort, and it can miss files. Back it with a PreToolUse hook that checks the path and blocks the call before it runs. A client hands you their systems because they trust that boundary. Data that never enters context never ends up in a transcript.
 
 
9. Package the service into slash commands
A client engagement is the same moves every time. Wrap them in /onboard and /weekly-report commands in .claude/commands/. One line runs the whole procedure: read the brief, route to the right agent, pull the data, format the output. You stop retyping prompts and start running a service.
 
10. Cron and routines run it hands-free
The work does not need you awake. A scheduled job runs the follow-up agent every morning and the reporter every Friday. Routines run server-side, so it continues after you close the laptop. The client wakes up to finished work and you wake up to a system that earned its retainer overnight.
 
 
11. Track every result in Notion
Connect Notion as the agency backend. Each client gets a row, each task a status, each result a number: calls recovered, replies sent, hours saved. This is the dashboard you show on the monthly call. It is also what lets the system learn, because Claude reads past performance and repeats what worked.
 
12. Make the output template the deliverable
Same format, every client, every week: the summary, the numbers, what changed, what is next. Save it as a template the /weekly-report command fills. A consistent artifact is what a client remembers and refers to a friend. Surprise formatting reads as amateur.
 
13. Offer free for 30 days, then bill on results
Read the client's last 12 months, run as a new variable for 30 days, then show the lift. Take a small cut of the extra revenue or a flat retainer once the numbers are in. No result, no bill. The offer removes the risk that kills most first calls, and it puts the proof on your side before money changes hands.
 
 
14. Clone the folder per client and scale
The whole agency lives in one folder: agents, commands, hooks, templates, deny rules. Clone it per client, swap the CLAUDE.md, and onboard in minutes. Subagents run several clients at once, so 5 retainers feel like 1. At that point you are not freelancing. You are running an agency with one employee who never sleeps.
