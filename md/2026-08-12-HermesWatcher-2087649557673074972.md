# A Hermes agent does not have to stay trapped inside the setup where you built it anymore.

## Post

A Hermes agent does not have to stay trapped inside the setup where you built it anymore.

That changes what a good agent can become.

Hermes now gives you two different ways to share an entire profile.

For a quick handoff

Use /export.

Hermes packages the profile into a file someone else can import.

That can include the agent’s personality, configuration, Skills, plugins, cron jobs, memories, sessions and other profile data. A Desktop export can even carry the theme and layout.

Useful when you want to send a working agent to a friend or colleague, move it to another machine, or make a snapshot before experimenting.

For something you want to keep distributing

Hermes also supports profile distributions.

Instead of sending a one-time file, you package the agent as a git repo containing things like:

• SOUL and configuration
• Skills
• cron jobs
• MCP connections
• plugins
Someone can install the whole agent with one command.
Then when you improve it, they can update their copy without replacing their own memories, sessions or API keys.
That is where this gets really interesting.
Build a great internal agent once and deploy it across a team.

Build a specialized agent for a business and reuse that foundation for future deployments.

Build something valuable enough to become part of a service or product.

Or hand a colleague the actual working agent instead of a document explaining how to rebuild it.

There is one important distinction.

An export can contain personal memory and session data, so inspect what you are sending.

A distribution is designed so the agent travels while the recipient keeps their own credentials, memories and sessions.

That changes how I think about agents like Havoc.

Once you put serious work into building a Hermes agent that is actually useful, it no longer has to remain a one-off setup on your computer.

It can become something portable, repeatable and shareable.
