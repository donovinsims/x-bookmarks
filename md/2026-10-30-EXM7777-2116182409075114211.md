working on the same project at the same time
now you have a writer and a builder who both want the same landing page
if they work in the same folder, one overwrites the other, and you end up untangling the mess by hand
git worktrees fix that, and the idea is dead simple: a worktree is a second desk on the same project
each desk gets its own folder and its own branch, and they all share the same project history, so two agents never write over each other's files
in practice, Claude Code rewrites the landing page copy at one desk while DeepSeek builds the signup form at another, each pushes its own branch, another agent reviews both, and you approve the merge
the rules that keep the desks clean:
decide which files each agent can touch before anything starts
one desk per task, each on its own branch
give each desk its own port so dev servers don't collide
merge one branch at a time, with tests between merges
every agent writes what it did in the log
the review step exists for a reason, because two agents can each make a change that looks fine alone and still break together, like one renaming something the other one still uses
separate desks, one merge lane, and you hold the key to it
