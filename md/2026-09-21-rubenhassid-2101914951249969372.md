## Jev design rules

Follow these exactly:

1. One Jev call per contact. Ask every question in that one call. Never chain calls per contact.

2. Every question and every threshold lives in ONE file: `lib/jev-questions.ts`. Nothing else in the codebase contains a question string or a threshold number. I will edit that file with you.

3. Write the full question in `instructions`. The key name is not sent to the model.

4. Every Choice has an `other` or `unclear` escape option.

5. Describe situations in criteria, not degrees. Say what belongs to each option and what does not.

6. Use backticked field paths in instructions, like `local_part` and `first_name`.

7. Pin the model version in the request once we have tuned thresholds. Log the versioned model ID that answered.

The questions to ask about each contact:

- `contact_kind` (Choice): what kind of sender is this address? Options: `individual_person` (a real human's personal or work address), `role_inbox` (a shared company inbox like info@, sales@, support@), `automated_sender` (noreply, notifications, newsletters, system mail), `institutional_id` (a student or employee number used as an address, digits before the @, at a university or large institution), `throwaway_or_spam` (disposable providers, random character strings, obvious spam), `unclear`.

- `name_looks_like_a_real_person` (Noul): does the combination of `first_name` and `last_name` read as a real human name? An emoji, a brand, initials only, or empty fields all mean no.

- `domain_kind` (Choice): `personal_freemail`, `company_or_organization`, `university_or_school`, `government`, `marketing_or_email_platform` (mailchimp, sendgrid, substack, beehiiv, hubspot and similar), `disposable_or_suspicious`, `unclear`.

- `looks_like_a_professional_contact` (Noul): does the address look like someone at a company or organization the user might do business with?

- One optional custom Noul. The UI has a text box labeled "Add your own yes/no filter" with a placeholder like "Is this person likely based in Israel?" or "Does this look like someone in tech?" If filled, add it as a fifth question named `custom_filter`. If empty, do not send it.

Bucketing logic (in code, in the same file as the questions, with the thresholds as named constants):

- REMOVE if `contact_kind.choice` is `automated_sender`, `institutional_id`, `throwaway_or_spam`, or `role_inbox`, AND `contact_kind.confidence >= KIND_CONFIDENCE_FLOOR`.

- KEEP if `contact_kind.choice` is `individual_person` AND `contact_kind.confidence >= KIND_CONFIDENCE_FLOOR`.

- REVIEW for everything else, including anything with `unclear` and anything below the floor.

- Start `KIND_CONFIDENCE_FLOOR` at 0.5. We will tune it against labeled rows.

- Also compute a `professional` flag from `looks_like_a_professional_contact.noul >= PROFESSIONAL_FLOOR` (start 0.7) so the user can filter Keep down to work contacts.

- Show the `custom_filter` probability as its own column when present.
