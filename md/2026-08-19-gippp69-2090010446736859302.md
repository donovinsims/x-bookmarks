# Kimi Ships a $39/Month Feature For Free. Here's How To Actually Set It Up (Full Guide)

## Post

TLDR: LangSmith charges per seat and per trace to show you which step in an agent run went wrong. Kimi catches a version of that same class of error for $0, using two things it already ships: a constraints file and a context graph. This is the exact setup, prompt by prompt.
 
1. The numbers first
LangSmith Plus: $39/seat/month, five-person team is $195/month before any usage
Cost of the Kimi setup below: $0, it's a markdown file and a graph export the swarm already produces
Failure category this setup targets: verification gaps, the largest of three in a 1,600-trace study of real multi-agent runs
Setup time the first time: under ten minutes
What it still doesn't cover: a coordinator crash mid-run with no resumable state behind it
 
2. Why this is worth setting up
LangSmith's whole pitch is showing you which step in a run went wrong, after the fact, for $39/seat/month plus trace fees. Kimi's Agent Swarm already ships two pieces that do a version of that job before the fact, for free. Most people never turn them on because nobody tells them there's a setup step. There is, and it's short.

5. Export the context graph so it outlives the session
Every entity a sub-agent touches becomes a node in Kimi's context graph, and every shared fact between two agents becomes an edge. Ask for the export at the end of a research-heavy run, then pull it into a place you actually keep:
 
Run this once per swarm launch and Obsidian's graph view becomes a running map of everything the swarm has ever connected, browsable between runs, not just inside one chat window.

The Skill supplies the procedure. The constraints file supplies the accumulated corrections. The context graph supplies the accumulated relationships. Nothing here retrains the model between sessions, the setup around it is what accumulates.
 
7. Where this setup stops working
None of this is checkpointing in the LangGraph sense: a saved, resumable snapshot of exact execution state. Moonshot's own documentation doesn't claim that either. Stall detection exists inside Agent Swarm, but what triggers it isn't published, and what happens if the coordinator itself fails mid-run isn't documented at all.
A constraints file stops a known mistake from repeating. It does nothing if the coordinator drops a 200-agent run at step 3,000 with no resumable state behind it. If a single run represents real spend, this setup is half the picture, build your own external checkpoint outside Kimi's infrastructure for the other half.
 
8. Quick reference
 
 
 
The point
The dashboard that tells you an agent already messed up costs $39 a month. The constraints file that stops some of those mistakes from happening costs three prompts and ten minutes. Neither one saves a run that crashes outright, and knowing which problem you're solving is most of the setup.
